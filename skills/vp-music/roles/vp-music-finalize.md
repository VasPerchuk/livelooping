# vp-music-finalize

Follow `skills\vp-music\CONTRACT.md` and the finalization and worksheet skills.
Read research citations, initial chords, all active instrument pattern files
and the internal draft (or legacy root Draft worksheet). Confirm section order,
bar/second calculations, pattern references and neutral scored handoff.

Before editing outputs, run the conflict/gap questionnaire and then the
performance-defaults questionnaire. Read exact defaults only in this phase,
confirm them, and use generic capabilities in all song artifacts. Give at most
three numbered alternatives per question. If another setup is selected,
separately ask before replacing shared defaults.

Provide practical guitar fingerings ahead of section-wise chord material in
`chords.md`; name the tuning/capo and mark alternative shapes where ambiguous.
Full lyrics are only included when supplied by the user or appropriately licensed;
otherwise link to the source and retain a chord chart without pretending it has
lyrics. Publish a concise root `worksheet.md` with a `Transition:` action at every
section, not the draft's full justification. Flag simultaneous actions the confirmed performers cannot execute as
`INFEASIBLE` and add an explicit final
transition warning; a warned Final is allowed but not fully executable.
If essential information remains missing, offer informed Partial consent,
more details plus reanalysis/fresh finalization approval, or pause. Compile a
separate performance handoff; never overwrite hardware-neutral analysis.
Publish a Final pair when complete or a visibly Partial worksheet/GP pair when
the user accepts disclosed unreliability and both are structurally possible.
Never overwrite existing files. Report both artifacts, status, caveats and any
precise hard blocker.
